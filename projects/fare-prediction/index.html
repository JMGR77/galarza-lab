Taxi Fare Prediction — Kaggle ML Challenge

A five-iteration machine-learning exercise progressing from Random Forest to a hybrid fare-formula approach, with a reported Kaggle evaluation MAE of 2.52019.

Model evolution & documented results

The project explored historical trip records, engineered useful features, evaluated Random Forest and identified a fare-pricing structure that improved performance. The strongest documented iteration combined the inferred pricing formula with a Random Forest fallback.

Five iterations, one engineering lesson

  1. Define the taxi fare regression problem, dataset fields and evaluation metric (MAE).
  2. Prepare data and experiment with Random Forest regression; reported local holdout MAE: 3.0984.
  3. Investigate relationships between distance, duration and fare components to understand pricing structure.
  4. Use a transparent pricing formula for applicable rows, with Random Forest as a fallback.
  5. Submit the hybrid approach; earlier discussion records a Kaggle MAE of 2.52019, with the formula used for 201 of 202 records and Random Forest for one.

Model interpretation

Illustrative discovered relationship: Fare = Base fare + (distance × per-kilometre rate) + (duration × per-minute rate). The underlying pricing coefficients are not supplied here; this is an explanation of the modeling strategy rather than a live fare calculator.

Evidence & reproducibility

The attached worksheet documents the competition steps and output schema (key, fare_amount). The original Python iteration files, prediction CSV, model binaries and a Kaggle submission receipt are not included in this release; the result values should be read as previously reported project results.

The 2.52019 result is from the Kaggle evaluation discussed previously; 3.0984 and 2.4147 are local holdout results under a different evaluation context. Neither demonstrates performance in a deployed ride-sharing pricing system.

Practical transfer

This exercise illustrates how understanding business rules and modeling data-generating mechanisms can complement predictive algorithms. The same discipline can support engineering cost estimates, project planning and operational analytics.
